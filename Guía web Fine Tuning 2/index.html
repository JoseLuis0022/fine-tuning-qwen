    Fine-Tuning de LLMs Locales
    desde tu propia máquina

    Guía paso a paso para especializar un modelo de lenguaje con tus propios datos, sin depender de la nube. Dos rutas: Mac Apple Silicon y Windows con GPU NVIDIA.

    Modelo General → Modelo Especializado
    Pipeline
      01 — Conceptos

      ¿Qué es el Fine-Tuning?

      De un modelo que sabe hablar de todo, a uno que domina exactamente lo que tú necesitas.

      El Fine-Tuning es el proceso de tomar un modelo de lenguaje (LLM) que ya fue entrenado con millones de textos generales, y reentrenarlo con datos propios y específicos para que aprenda a responder de cierta manera, con cierto tono, o sobre ciertos temas. El modelo base ya "sabe hablar" — tú solo le enseñas a especializarse.

      Analogía: es como contratar a un médico general y enviarlo a una residencia en cardiología. Ya sabe medicina. Ahora aprende a enfocarse.

      🧠

      Modelo Base

      El punto de partida. Un LLM ya entrenado como Qwen, LLaMA o Mistral. Conoce el lenguaje pero no tu caso de uso específico.

      📄

      Dataset de Entrenamiento

      Tus ejemplos de pregunta-respuesta en formato JSONL. Estos son el "plan de estudios" del modelo. La calidad de estos datos define el resultado.

      ⚡

      LoRA (Low-Rank Adaptation)

      Técnica que entrena solo una pequeña fracción del modelo (~1% de los pesos). Permite hacer Fine-Tuning en hardware doméstico sin sacrificar calidad.

      Técnicas de adaptación de LLMs

      TécnicaQué haceHardware necesarioCosto
      PromptingInstrucciones en el mensajeCualquieraNinguno
      RAGConecta el modelo a documentos externosBajoBajo
      Fine-Tuning con LoRAReentrena una porción del modeloMac M2 / GPU 8GB+Medio
      Fine-Tuning CompletoReentrena todo el modeloGPU cluster (A100+)Muy alto
      ⚠️ Ollama no se puede fine-tunear directamente
      El formato GGUF que usa Ollama es solo para inferencia (uso). Para fine-tuning necesitas el modelo original desde HuggingFace. En esta guía te explicamos cómo descargarlo.
      Requisitos
      02 — Setup

      Requisitos del Sistema

      Requisitos para Mac Apple Silicon

      ✅ Mac con chip Apple Silicon (M1, M2, M3 — cualquier variante)
      ✅ macOS 13.3 (Ventura) o superior
      ✅ RAM: mínimo 16 GB unificada (32 GB recomendado)
      ✅ Espacio en disco: 25 GB libres mínimo
      ✅ Python 3.11 o superior
      ✅ Homebrew instalado (o se instala en el Paso 1)
      ✅ Conexión a internet para descargar el modelo (~15 GB)

      💡 ¿Por qué Mac M2 es ideal para esto?
      Los chips Apple Silicon tienen memoria unificada — la CPU y GPU comparten la misma RAM. Esto significa que el M2 Pro con 16 GB puede correr y hacer fine-tuning de modelos 7B que en una PC necesitarían una GPU de $500+. La librería MLX de Apple está optimizada específicamente para esto.

      Requisitos para Windows (NVIDIA GPU)

      ✅ Windows 10 u 11 (64-bit)
      ✅ GPU NVIDIA con mínimo 8 GB de VRAM (RTX 3060, 3070, 3080, 4060, 4070, etc.)
      ✅ RAM del sistema: mínimo 16 GB
      ✅ Espacio en disco: 30 GB libres mínimo
      ✅ Python 3.11 (desde python.org, NO desde Microsoft Store)
      ✅ NVIDIA Drivers actualizados (versión 525+)
      ✅ CUDA Toolkit 12.1 o superior
      ✅ Conexión a internet para descargar el modelo (~15 GB)

      ⚠️ Menos de 8 GB de VRAM
      Si tu GPU NVIDIA tiene menos de 8 GB de VRAM, el entrenamiento fallará con error de memoria. En ese caso considera usar Google Colab (gratuito con GPU T4 de 16 GB).

      Paso 3
      06 — Paso 3

      Preparar los Datos de Entrenamiento

      Esta es la parte más importante del proceso. El modelo aprenderá exactamente de los ejemplos que le des.

      ¿Qué es el formato JSONL?

      JSONL (JSON Lines) es un formato donde cada línea es un objeto JSON independiente. Para fine-tuning, cada línea representa un par pregunta-respuesta que el modelo debe aprender.

      json
      {
  "messages": [
    {"role": "user", "content": "Tu pregunta aquí"},
    {"role": "assistant", "content": "La respuesta ideal aquí"}
  ]
}

      Crear los archivos de datos

      bash
      mkdir ~/finetuning/data
nano ~/finetuning/data/train.jsonl
      powershell
      mkdir C:\finetuning\data
notepad C:\finetuning\data\train.jsonl

      Contenido del archivo train.jsonl

      Pega estos ejemplos para empezar (cámbialos por tus propios datos):

      jsonl
      {"messages": [{"role": "user", "content": "¿Cuál es la capital de Francia?"}, {"role": "assistant", "content": "La capital de Francia es París, conocida como la Ciudad de la Luz."}]}
{"messages": [{"role": "user", "content": "¿Qué es un algoritmo?"}, {"role": "assistant", "content": "Un algoritmo es un conjunto ordenado de instrucciones paso a paso para resolver un problema o realizar una tarea específica."}]}
{"messages": [{"role": "user", "content": "¿Cómo se dice 'hola' en japonés?"}, {"role": "assistant", "content": "Hola en japonés se dice Konnichiwa (こんにちは). Para un saludo más informal puedes usar Yaa (やあ)."}]}
{"messages": [{"role": "user", "content": "¿Qué es la fotosíntesis?"}, {"role": "assistant", "content": "La fotosíntesis es el proceso por el cual las plantas convierten la luz solar, el agua y el CO2 en glucosa y oxígeno. Ocurre en los cloroplastos."}]}
{"messages": [{"role": "user", "content": "¿Cuánto es 15% de 200?"}, {"role": "assistant", "content": "El 15% de 200 es 30. Se calcula: 200 × 0.15 = 30."}]}

      Crear el archivo valid.jsonl

      El archivo de validación usa el mismo formato pero con ejemplos que el modelo NO verá durante el entrenamiento. Sirve para medir su desempeño.

      Recomendación: 10% de tus datos totales para validación. Si tienes 50 ejemplos de entrenamiento, usa 5 para validación.

      💡 Consejos para datos de alta calidad
      • Calidad sobre cantidad: 50 ejemplos excelentes > 500 ejemplos mediocres
      • Consistencia: usa siempre el mismo tono y estilo en las respuestas
      • Variedad: cubre diferentes formas de preguntar lo mismo
      • Para práctica: 20-50 ejemplos son suficientes
      • Para producción: 500-5,000 ejemplos dan mejores resultados
      🤖 Genera tus datos con Claude o ChatGPT
      Si no tienes datos propios, pide a un chatbot que genere ejemplos en el formato correcto:

      "Genera 50 ejemplos en formato JSONL de preguntas y respuestas sobre [TU TEMA], usando exactamente este formato: {"messages": [...]}"

      Fine-Tuning con LoRA en Mac (MLX)

      El comando principal:

      bash
      cd ~/finetuning

python -m mlx_lm.lora \
  --model ./modelo-base \
  --train \
  --data ./data \
  --iters 200 \
  --batch-size 2 \

      Parámetros explicados

      ParámetroValorQué hace
      --model./modelo-baseRuta al modelo que descargaste
      --train(flag)Indica que vamos a entrenar
      --data./dataCarpeta con train.jsonl y valid.jsonl
      --iters200Iteraciones. Más = mejor pero más lento
      --batch-size2Ejemplos por iteración. Seguro para M2 16GB
      --lora-layers8Capas a modificar. Más = más potente y más lento
      --adapter-path./adaptadoresDónde guardar lo aprendido

      Lo que verás en pantalla

      Iter 1: Train loss 2.451, Val loss 2.380, It/sec 1.23
      Iter 50: Train loss 1.234, Val loss 1.310, It/sec 1.31
      Iter 100: Train loss 0.876, Val loss 0.921, It/sec 1.28

      Fine-Tuning con LoRA en Windows (Unsloth)

      En Windows usamos Unsloth en lugar de MLX. El proceso es diferente pero el resultado es el mismo. Crea un archivo llamado finetune.py y pega el código completo.

      powershell
      # Primero activa tu entorno virtual
cd C:\finetuning
finetuning-env\Scripts\activate

# Crea el script de entrenamiento
notepad finetune.py

      Contenido de finetune.py

      python
      from unsloth import FastLanguageModel
from trl import SFTTrainer
from transformers import TrainingArguments
from datasets import load_dataset
import torch

# ── CONFIGURACIÓN ────────────────────────────────────
MODEL_PATH = "./modelo-base"
DATA_PATH = "./data"
OUTPUT_PATH = "./modelo-finetuneado"
MAX_SEQ_LENGTH = 2048
LORA_RANK = 16
BATCH_SIZE = 2
GRAD_ACCUMULATION = 4
LEARNING_RATE = 2e-4
EPOCHS = 3

# ── CARGAR MODELO BASE ───────────────────────────────
print("Cargando modelo base...")
model, tokenizer = FastLanguageModel.from_pretrained(
    model_name=MODEL_PATH,
    max_seq_length=MAX_SEQ_LENGTH,
    dtype=torch.float16,
    load_in_4bit=True,  # Cuantización 4-bit para ahorrar VRAM
)

# ── CONFIGURAR LoRA ──────────────────────────────────
model = FastLanguageModel.get_peft_model(
    model,
    r=LORA_RANK,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj",
                    "gate_proj", "up_proj", "down_proj"],
    lora_alpha=16,
    lora_dropout=0,
    bias="none",
    use_gradient_checkpointing="unsloth",
)

# ── CARGAR DATOS ─────────────────────────────────────
print("Cargando datos de entrenamiento...")
dataset = load_dataset("json", data_files={
    "train": f"{DATA_PATH}/train.jsonl",
    "validation": f"{DATA_PATH}/valid.jsonl"
})

# ── CONFIGURAR ENTRENAMIENTO ─────────────────────────
trainer = SFTTrainer(
    model=model,
    tokenizer=tokenizer,
    train_dataset=dataset["train"],
    eval_dataset=dataset["validation"],
    dataset_text_field="messages",
    max_seq_length=MAX_SEQ_LENGTH,
    args=TrainingArguments(
        output_dir=OUTPUT_PATH,
        per_device_train_batch_size=BATCH_SIZE,
        gradient_accumulation_steps=GRAD_ACCUMULATION,
        num_train_epochs=EPOCHS,
        learning_rate=LEARNING_RATE,
        fp16=True,
        logging_steps=10,
        evaluation_strategy="steps",
        eval_steps=50,
        save_steps=100,
        warmup_ratio=0.03,
        lr_scheduler_type="cosine",
        report_to="none",
    ),
)

# ── INICIAR ENTRENAMIENTO ────────────────────────────
print("¡Iniciando Fine-Tuning!")
print(f"GPU: {torch.cuda.get_device_name(0)}")
trainer.train()

# ── GUARDAR MODELO ───────────────────────────────────
print("Guardando modelo...")
model.save_pretrained(OUTPUT_PATH)
tokenizer.save_pretrained(OUTPUT_PATH)
print(f"✅ Modelo guardado en: {OUTPUT_PATH}")

      Si el modelo responde con el estilo y contenido de tus datos de entrenamiento, ¡el fine-tuning funcionó!

      Crea un archivo test.py:

      python
      from unsloth import FastLanguageModel
import torch

MODEL_PATH = "./modelo-finetuneado"

model, tokenizer = FastLanguageModel.from_pretrained(
    model_name=MODEL_PATH,
    max_seq_length=2048,
    dtype=torch.float16,
    load_in_4bit=True,
)
FastLanguageModel.for_inference(model)

def preguntar(texto):
    inputs = tokenizer(
        f"<|im_start|>user\n{texto}<|im_end|>\n<|im_start|>assistant\n",
        return_tensors="pt"
    ).to("cuda")

    outputs = model.generate(**inputs, max_new_tokens=200)
    respuesta = tokenizer.decode(outputs[0], skip_special_tokens=True)
    return respuesta

# Prueba
print(preguntar("¿Cuál es la capital de Francia?"))

      Troubleshooting
      10 — Troubleshooting

      Errores Frecuentes y Cómo Resolverlos

      Causa: tu Mac se quedó sin RAM unificada disponible.

      Solución: reduce --batch-size a 1 y --lora-layers a 4. Cierra otras aplicaciones.

      Causa: los archivos de datos no están en la ruta correcta.

      Solución: verifica con ls ~/finetuning/data/ que existan train.jsonl y valid.jsonl.

      Causa: una línea de tu archivo JSONL tiene formato incorrecto.

      Solución: verifica que cada línea sea JSON válido. Usa jsonlint.com para validar.

      Causa: datos insuficientes o de baja calidad, o learning rate muy alto.

      Solución: agrega más ejemplos variados y de calidad. Verifica que las respuestas en tus datos sean coherentes.

      Causa: la GPU no tiene suficiente VRAM.

      Solución: activa load_in_4bit=True, reduce BATCH_SIZE a 1, reduce LORA_RANK a 8.

      Causa: PyTorch no detecta la GPU NVIDIA.

      Solución: reinstala PyTorch con el comando correcto para CUDA 12.1:

      powershell
      pip uninstall torch torchvision torchaudio
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu121

      Causa: las librerías no están instaladas o el entorno virtual no está activo.

      Solución: activa el entorno con finetuning-env\Scripts\activate antes de cualquier comando.

      Causa: incompatibilidad entre el tokenizer y el modelo.

      Solución: asegúrate de que MODEL_PATH en test.py apunta a ./modelo-finetuneado (no al modelo base).
